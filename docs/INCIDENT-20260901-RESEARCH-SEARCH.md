# 研究搜索结果污染复盘（2026-09-01）

## 结论

研究搜索曾把与主题无关的搜索引擎结果写入创作素材库。实战复核确认，这不是用户搜索方向的问题，而是查询泛化、中文相关性计算不足，以及搜索源异常返回共同造成的。

修复后，系统不会再把低相关结果写入素材库；当外部搜索源不可用或结果不相关时，接口会安全返回 0 条并保留错误状态。

## 故障表现

历史结果中出现了以下明显无关页面：

- “学院竞争”得到“封闭针”医疗页面；
- “慢热互信”得到“慢”字典页面；
- “争风吃醋”得到 YouTube、Outlook、Microsoft 页面；
- “同学变小迷弟”得到 WhatsApp、Facebook、Windows 帮助页面。

素材库页面又把多轮搜索结果累计显示为“公开网页研究”，因此用户看到的 22 条来源并非单次搜索，而是污染期多次搜索累积的结果。

## 根因

1. `src/outline/engine.ts` 的 `safeQueries` 只识别少数固定词。未命中分类词的主题会退化为“长篇故事人物弧线与结构”，原始主题被丢失。
2. `server/web-research.ts` 原本在所有结果相关性得分为 0 时仍返回原始结果，导致搜索引擎的导航页、推荐页和错误页被当作研究来源。
3. 相关性计算按空格切词，不适合中文；长中文短语经常被当成一个整体，无法命中标题和摘要。
4. 当前 VPS 的 DuckDuckGo 会触发人机验证；Bing 兜底在实测中对中文研究主题返回字典、产品帮助和其他无关页面。搜索源异常时，旧逻辑没有拒收。

## 修复

- 原始主题始终保留，分类词只做扩展，不再替换用户意图。
- 增加关系推进、校园竞争、日常场景、悬疑伏笔等主题分类。
- 中文关键词支持片段匹配。
- 相关性不足的结果直接丢弃，不再使用“全零分也保留原始结果”的兜底。
- 网页来源按 URL 去重。
- 清理污染期的网页来源和网页机制；小说消化生成的 `doc-*` 来源与机制未删除。

## 实战验证

在修复后连续搜索：

- 慢热互信
- 争风吃醋
- 悬疑伏笔

三次均保留了正确主题，但由于当前 Bing/DuckDuckGo 没有提供足够相关的结果，均安全返回 0 条，没有重新污染素材库。直接检查搜索源也复现了 Bing 返回字典、Microsoft 和酒店页面的异常行为。

- 小说研究文档：26 部；

## 当前边界与后续

研究搜索现在遵循“宁可无结果，不收录错结果”。要恢复稳定的有效网页研究，需要配置可靠的搜索 API 或内部搜索代理，并让其返回明确的标题、URL、摘要字段。不能继续把当前 Bing HTML 兜底当作高质量研究源。

运维排查时应区分：

- `sources=[]`：相关性门槛拒绝了结果，或搜索源没有可用结果；
- `error`：网络、代理或搜索源请求失败；
- 有来源但无提炼：来源存在，但模型没有产出合格机制。
