# 导演室（Story Director）

> 2026-08-20。本文是「导演室」的用户参考与实现定位：入口、真实功能边界、它和系统助手/编剧室的区别，以及建议如何转成大纲。权威设计见 `docs/PLAN-OUTLINE-SYSTEM.md`。

## 一句话

导演室是一个能实时讨论当前剧情、并给出下一段走法的故事导演：你直接说想经历什么、哪里不满意、想靠近或避开什么，它综合读取当前正文、人物状态、世界与生态工件，给出可执行的即时建议；只有你明确要形成的长期方向才进建议箱、由你确认后写入动态大纲。它不代替主演写正文，也不把建议当已发生事实。

## 入口与界面

- 主输入框发送按钮右侧的显式按钮「导演室」，点击打开。
- 也被「面板」下拉里的系统项和欢迎页快捷入口调用。
- 桌面为可全屏的宽弹窗；移动端全屏。
- 九页分组侧栏：**创作**（创作对谈 / 提案审阅）、**故事**（故事脉络 / 人物成长 / 伏笔追踪）、**资料**（藏书消化 / 研究搜索 / 创作素材库）、**系统**（演出回放 / 版本与设置）。
- 创作对谈的输入栏上方为七种讨论模式，下方工具栏含「首次规划」「校准」「研究灵感」「清空讨论」。清空讨论只清 `rp-outline-chat`，不影响提案和大纲。

## 和系统助手的区别

| | 导演室 | 系统助手（耳麦） |
|---|---|---|
| 职责 | 剧情、人物、对白、节奏、伏笔、**演出诊断** | 配置、诊断、记忆、外部服务 |
| 读什么 | 当前正文、rp-state、世界、生态、文学画像、导演工件、大纲、**Session Tree 诊断数据** | 剧情快照 + 系统工具面 |
| 产出 | 即时导演建议 + 待确认大纲提案 + **只读回合诊断** | 运维结论 / 系统修改 |
| 写什么 | 只写 `rp-outline-chat` 讨论记录；大纲需确认；**诊断只读不写** | 角色卡、记忆、面板等系统面 |

## 七种讨论模式

模式决定导演的重心，输入框会用该模式的提示词预填：

- **综合编剧**：长期路线与当前场景一起讨论。
- **下一拍**：从当前已提交正文往下，给起手动作、角色主动性、压力来源、玩家空间、备选走法和自然停点。
- **下一段对白**：给对话意图、潜台词、信息交换和少量可参考的语气/示例，不生成需要落树的定稿正文。
- **角色反应**：当前人物此刻最自然的反应、主动动作、顾虑和行为上限；必须服从角色卡与近期事实。
- **节奏诊断**：检查拖沓、跳跃、重复、失焦、角色被动或关系推进过快，并给可操作修正。
- **日常剧情**：策划可直接拿来演的完整小剧情卡。不是流水账活动清单，而是包含表面活动、发起者与隐藏目的、至少一个发糖点、低烈度冲突或误会、关系微变化、角色行为边界、用户可选分叉和自然停点。可从小说研究库引用日常叙事机制，但禁止复刻原作专名和独特事件。

## 本拍诊断

“本拍诊断”是导演室内的只读演出后台。它按当前分支列出最近最多 20 回合的完整演出流水线，把每一拍拆成当前实现的独立节点：

```
文学连续性
→ Stitches 导演
→ 生态抵达
→ 主演分段演出
→ 角色账本
→ 拍后事实信封
→ 世界转移提案
→ 世界转移审计
→ 世界原子提交
→ 生态 aftermath
→ 独立谢幕格式
→ 大纲异步校准
```

当前实现不再包含“逐角色排演”节点；人物主动性由 Stitches 导演统一处理，场面编排直接读取导演与生态适配候选。

每个节点区分以下状态：

| 状态 | 含义 |
|---|---|
| 成功 | 该阶段正常完成并产出有效工件 |
| 降级 | 该阶段失败但系统降级继续（如生态降级快照） |
| 跳过 | 该阶段未触发或未开启（正常情况，不是失败） |
| 复用 | 使用了上一拍的缓存工件 |
| 失败 | 该阶段调用或解析失败 |
| 被拒绝 | 提案/审核被拒绝（世界提案被审计拒绝 / 大纲提案被用户拒绝） |
| 已提交 | 该阶段权威数据已成功写入分支树 |
| 待确认 | 需要用户在建议箱确认才能生效 |
| 稳定 | 检查完成后没有需要修改的内容 |
| 审计通过 | 审计检查通过（通常紧接着被提交） |
| 不可用 | 历史消息缺少诊断元数据 |

**主演演出区域**可查看：
- 思考段数、工具组数、正文段数
- 稿段数量、被拒收次数
- 总耗时（秒）、输出 token

**账本区域**精确区分：
- 账本已提交
- 场记确认本拍无需新账本快照
- 场记输出不可解析（含错误原因）
- 场记因切换分支被丢弃

**世界链区域**失败时能定位阶段：
- 事实信封：已提取带证据事实 或 事实信封失败
- 世界提案：已通过确定性预审 / 被预审拒绝 / 失败
- 世界审计：审计通过 / 审计拒绝 / 跳过（提案未进入审计）
- 世界提交：已提交 / 本拍没有到期变化，世界保持稳定 / 保留上一快照

**可展开区域**包括：
- 各节点的安全结构化工件（连续性位置、导演场景压力等）
- 分支提交记录（类型、状态、摘要）
- 账本修改审计（角色、字段、来源指纹、验证状态）
- 独立谢幕格式原文（最多 32,000 字符，超出标记“已截断”）

**数据来源与安全**：
- 数据从当前 Session Tree 已有条目动态投影，不调用模型、不建立第二套剧情状态。
- 本拍工作流不再运行逐角色排演；人物主动性由拍前导演统一处理，旁路调用不再随出场人数线性增加。
- 不发送完整 prompt、生态秘密/幕后真相、世界书来源路径、隐藏 reasoning。
- 旧会话缺少工作流工件的消息自动跳过；手动大纲操作不混入自动校准记录。
- 打开诊断页后每 5 秒自动刷新；后台校准完成后无需手动刷新。
- 切换会话、导航分支、清空模块时缓存自动失效。

## 即时建议卡（sceneAdvice）

导演的即时回答会额外整理成一张建议卡，包含两个层面：

**幕后方向**（导演看到的部分）：
- 推荐下一拍核心（`recommendedBeat`：希望哪条关系/线索/压力发生变化）
- 下一段从哪里起手（`openingMove`）
- 角色各自的主动动作
- **建议聊天对象**：找谁、为什么此刻适合找他/她、从什么公开话题切入、可能的拒绝或误会
- 混合路线：当前不宜直接聊天时，先观察/先做事/等待什么、再找谁，以及切入条件

**用户可以亲手做的事**（从玩家视角出发）：
- 可以做什么（`playerObjective`：用户从此刻处境、凭自己看得见的理由会去做的具体动作）
- 为什么现在做（`naturalReason`：从当前剧情里找得到的自然理由）
- 希望推动什么（`intendedConsequence`：一段关系、一条线索、一个境地的变化方向——不需要保证必然发生）

此外还有对白线索、压力、玩家空间、自然停点、机制不同的备选走法。

这些是当前场景的非事实投影，不会自动进入正文或改状态。

## 日常剧情卡（dailyPlan）

当选择「日常剧情」模式讨论时，导演会返回一张或多张完整的日常剧情卡，每张包含完整小剧情的所有要素：

- **标题与类型**：发糖/误会/轻冲突/情报/混合
- **地点与时长**：故事内持续时间
- **参与人物与发起者**：谁主动发起，表面理由是什么
- **发起者的隐藏目的**：表面活动下没有直说的真实意图
- **发糖节点**：具体哪些时刻产生亲近感（不写正文）
- **小冲突**：低烈度摩擦的来源
- **误会**：双方如何误读对方的言行
- **角色边界**：每个角色绝不能越过的行为底线
- **关系变化**：这段结束后关系具体改变了什么
- **用户可选分叉**：玩家可以改变方向的走法
- **自然停点**：把笔交还用户的时机
- **后续种子**：可以接下去发展的剧情方向
- **研究引用**：使用了小说研究库中的哪些日常叙事机制

日常剧情卡只写入 `rp-outline-chat`，不是已发生事实。用户确认的方向才通过现有 proposal 机制进入长期大纲。

## 小说研究

「研究搜索」页签是导演室对外的公开资料研究入口：输入想研究的话题（或留空用默认话题），
系统生成去隐私的检索式（`#safeQueries`，剔除角色名/用户名），搜索公开书评、影评与叙事分析
摘要，逐条展示搜到的来源（标题/URL/摘要），再由 `叙事研究提炼` Skill 提炼成可复用机制，
一轮结束即入库创作素材库（跨卡共享），并展示本轮提炼结果与来源标注。
需先在「版本与设置」启用联网研究（研究方式 manual/auto）；入口 `POST /api/outline/research/search`。

「藏书消化」页签是小说全文的后台研究工作台，不进入台上正文流程。它支持：

- 上传用户有权使用的 `.txt` / `.epub` 文本
- 手动提交公开 Kakuyomu 作品 URL
- 点击「自动选取 3 部小说」，立即按配置的题材关键词搜索，排除已入库作品并将最多 3 部送入消化队列
- 每天本地时间 05:00 自动从 Kakuyomu「学园·日常」「现代·日常·社会人」「青春·日常」检索候选，最多新增 3 部
- 观察多部文档同时消化的 `cleaning / mapping / reducing / extracting / ready` 状态
- 展开查看全书梗概、主线事件链、人物弧线、钩子节奏、弧线摘要、日常剧情卡和可调度素材

研究搜索页另有“自动搜索主题”入口：它按 `researchSearchSchedule.topics` 顺序执行普通联网研究，和每日定时任务共用运行锁、主题去重、状态持久化与部分失败语义；可通过 `GET /api/outline/research/search/schedule` 查看状态，`POST /api/outline/research/search/schedule/run` 立即触发。

手动选书与每日自动任务复用同一套搜索、去重和入队逻辑，只排除已经存在的 `doc-*` 文档，不会删除已有研究；同一时刻只运行一个选书任务。新文档按当前角色卡绑定并进入研究库。消化提炼出的机制、日常卡与素材是抽象可复用套路，**创作素材库跨卡共享**（所有角色卡都能参考任意卡消化的小说素材）。服务重启后会从已落盘 digest 断点恢复。全文只在服务器本地清洗和分块读取，不进入台上上下文；大纲模型只收到安全投影后的有限梗概、机制和按 `focus`/问题筛选的素材。

小说研究的并行边界是文档级最多 3 部；同一文档内部仍顺序执行，研究库最终写入仍串行化。暂停或删除一部不会取消其他文档。

配置入口：

```json
"novelDigest": {
  "enabled": true,
  "autoSchedule": {
    "enabled": true,
    "hour": 5,
    "minute": 0,
    "maxPerRun": 3,
    "queries": ["学園 日常", "現代 日常 社会人", "青春 日常"]
  }
}
```

请仅抓取或上传你有权用于个人研究的文本。梨园不提供付费或盗版来源，也不依赖外部 Windows 下载器；服务器使用 Kakuyomu 公开作品解析直接生成 UTF-8 TXT。

## 建议如何变成大纲（不自动成立）

1. 讨论过程中，导演只会在他判断值得固化为长期方向时才附带一个 `proposal`。
2. 高风险修改（终局、人物核心重释、不可逆关系、秘密揭示、大范围改写）默认必须人工确认。
3. 提案进入「建议箱」，可查看审计原因和风险；点「接受」携带 proposal hash 才写入 `rp-outline`。
4. 接受了才修订当前分支的动态大纲；拒绝或忽略都不会改变任何权威。

## 它写什么、不写什么

- 只作为分支条目写入 `rp-outline-chat`（讨论记录与场景建议），随回档、变体和世界线恢复。
- 不进入主演正文历史，不改变 `rp-state`、`rp-world-state`、`rp-ecology-state`。
- 主角的自愿行动、感情、承诺与选择永远由你决定，导演只给方案。

## 实现要点

- 后端 `src/outline/*` 提供 Proposal/Audit/Commit 与严格解析；规则在 `skills/`。
- `src/stage/diagnostics.ts` 提供本拍诊断只读投影；`GET /api/turn-diagnostics` 无模型调用。
- 前端 `web/src/planning/` 是独立工作台，直接调 `/api/outline/*` 与 `/api/turn-diagnostics`。
- 诊断页每 5 秒自动轮询，并发请求保护，离开标签页时失效。
- 模型插头：`outlineChat / outlineBootstrap / outlineReconcile / outlineResearch / outlineAudit`，可在「设置 → 模型」分别指定模型。
- 联网研究默认关闭；开启后也会对用户姓名和角色名脱敏，不发送私人原始文本。
- 大纲异步校准运行时状态由 `server/main.ts` 内存 Map 管理，切换/重载会话时清空。

## 研究搜索的结果边界（2026-09-01）

研究搜索会保留用户原始主题并执行中文关键词相关性过滤。搜索源返回的导航页、字典页、产品帮助页或其他低相关结果不会进入创作素材库；如果当前搜索源（DuckDuckGo/Bing 兜底）触发验证或返回异常结果，页面会显示 0 条来源。这表示本轮没有通过质量门槛，不代表可以把结果当作研究事实。完整事故记录见 [`docs/INCIDENT-20260901-RESEARCH-SEARCH.md`](INCIDENT-20260901-RESEARCH-SEARCH.md)。


## 导演室模块化目录（2026-09-01）

导演室采用独立模块组件，不把业务逻辑继续堆回 `StoryPlanningWorkbench.tsx`：

- `web/src/planning/modules/registry.ts`：模块注册表与分组导航；
- `DiagnosticsModule.tsx`：演出诊断；
- `CorpusModule.tsx`：藏书消化；
- `ResearchSearchModule.tsx`：研究搜索与自动任务；
- `MemoryModule.tsx`：剧情记忆与审计；
- `StoryMapModule.tsx`：故事脉络；
- `CharactersModule.tsx`：人物成长；
- `ForeshadowingModule.tsx`：伏笔追踪；
- `ProposalsModule.tsx`：提案审阅；
- `VersionsModule.tsx`：版本与工作模式；
- `WorldModule.tsx`：世界画像与世界运行态；
- `SystemModule.tsx`：配置、模型和后台任务总览。

模块通过 props 接收页面状态，通过既有 API 读写；模块之间不共享隐式业务变量。高风险写入仍回到原有审计链，不在只读总览模块中复制一套提交逻辑。

## 资料库展示边界（2026-09-02）

“创作素材库”只展示已经提炼出的可复用机制，并按来源固定分为两个独立区块：

- **网页研究素材**：来自公开网页搜索的来源与提炼机制；
- **藏书消化素材**：来自本地上传或公开 Kakuyomu 作品消化的提炼机制。

两类素材共用搜索框和可信度筛选，但不会在页面上混排。完整小说梗概、弧线、日常剧情卡和可调度素材仍在“藏书消化”页按文档展开；原始网页来源和搜索历史仍在“研究搜索”页查看。这个分区只改变前端投影，不改变后端研究库、跨卡共享和模型择取逻辑。
