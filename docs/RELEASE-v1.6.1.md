# v1.6.1（2026-09-01）：导演室模块化与研究链路稳定性

本版将梨园现有能力整理为导演室内彼此独立的前端模块，并修复研究搜索与小说消化在生产环境中的关键稳定性问题。

## 导演室模块化

- 导演室导航由 `web/src/planning/modules/registry.ts` 统一注册和分组。
- 每项能力保持独立组件：演出诊断、藏书消化、研究搜索、剧情记忆、故事脉络、人物成长、伏笔追踪、提案审阅、版本设置、世界状态和系统总览。
- `StoryPlanningWorkbench.tsx` 只负责页面协调、公共状态和创作对谈；具体模块业务 UI 不再继续堆入主文件。
- 世界状态和系统总览使用既有 API 的只读投影，不复制配置写入、审计或权威状态逻辑。
- 高风险大纲写入继续沿用 Proposal/Audit/Commit 链路；模块之间不共享隐式业务状态。

## 研究搜索

- 原始研究主题始终保留，中文主题使用片段相关性匹配，避免被泛化查询替换。
- 低相关页面、导航页、字典页、产品帮助页和搜索引擎异常页面不再进入创作素材库。
- 搜索源触发验证或返回异常结果时安全返回 0 条，并保留可诊断的错误状态；“无结果”不代表可以把原始页面当作研究事实。
- 研究搜索支持手动执行和每日自动主题任务；任务状态、去重和运行锁统一持久化。

## 小说研究

- 藏书消化支持本地上传、公开 Kakuyomu URL、手动选取和每日自动选书。
- 每日自动选书默认在本地时间 05:00 运行，最多新增 3 部；同一时间只运行一个选书任务。
- 文档级最多并行 3 部，单文档内部仍顺序处理；服务重启后从已落盘 digest 断点恢复。
- 研究旁路改为读取 `stream.result()` 的最终消息，关闭额外的 SDK 重试，单次调用硬超时 60 秒。
- 增强提炼部分失败时降级为 `ready`，不会因非核心产物失败而反复消化全文。
- 完整根因、修复细节和生产验证见 [`INCIDENT-20260901-NOVEL-DIGEST.md`](INCIDENT-20260901-NOVEL-DIGEST.md)。

## 2026-09-14 运行时修订

- 移除正文关键路径中的逐角色模型排演，避免旁路调用随出场人数线性增长；导演统一处理角色主动性。
- 支持预设中的 `大概3000字`、`约3000字左右`、`不少于2000字` 等自然语言篇幅目标。
- 明确长篇目标时，正文不足会触发封笔软门禁；约 3000 字目标动态允许最多 6 条路标。
- 模型选择支持保存即热切换：连接面板与设置页会同步当前会话模型和主演正文插头，不要求重启服务。
- 对带函数工具的 OpenAI 兼容模型收紧 reasoning effort 透传，仅向明确支持的模型发送该参数。
