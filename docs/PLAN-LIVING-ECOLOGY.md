# PLAN-LIVING-ECOLOGY：鲜活世界生态系统

> 本文定义全局叙事原型池、角色卡生态池与分支生态运行态的权威边界。目标不是给用户随机刷任务，
> 而是让用户成为持续运行世界中的探索者——世界先于用户存在，也独立于用户运转。
>
> **2026-08-17 定稿（关键路径分级后）**：生态全链路已落地并经受实弹修复。本文是生态相关改动的唯一靶子。

## 三层权威

```text
.liyuan/ecology/global-pool.json        = 全局叙事原型池，跨卡共享
.liyuan/ecology/cards/<card-key>.json  = 角色卡生态池，按卡复用
rp-ecology-state                       = 当前会话分支上的人物/地点/日程/事件权威
```

- **全局池**保存从公开小说、电影、游戏和现实活动中抽象的叙事发动机及来源，不保存原台词、专名和完整反转。
- **卡池**保存当前作品的世界语法、人物行动语法和适配模板，不保存某会话已发生事实。
- **运行态**保存人物生活、地点活动、公开/待发现/幕后事件；是 `f(分支)`，随回档、变体和世界线恢复。
- 三层各自有独立模型插头：`ecologySearch`（检索规划）、`ecologyGlobal`（全局池）、`ecologyCard`（卡池）、`ecologyRuntime`（人物/场所运行态）。默认继承剧情总插头，前端可分别覆盖。

## 一拍流程（关键路径分级，最终形态）

正文开始前的关键路径**只保留 arrival 与连续性**；搜索与双池更新彻底移出关键路径：

```text
用户输入
  → 消费已就绪（ready）的上一批双池候选；未就绪则继续用磁盘现有池，绝不等待
  → arrival（生态运行模型）┐
  → 连续性（文学连续性模型）├→ 并行（正文必须等）
  → Stitches 导演（同时吸收两份结果）
  → 主演分段演出（beat_plan → draft_append → draft_seal）
  → 角色账本（world_state_update → rp-state）
  → 后台世界链（事实信封→提案→审计→Commit）┐
  → 人物生态 aftermath                    ├→ 并行计算（不影响正文首字）
  → 顺序落树（rp-world-audit → rp-world-state → rp-ecology-state）
  → 长局压缩
  → 启动下一批后台双池备料（查询规划 → 搜索批次并发 → 全局池 → 卡池）
```

关键语义：

- **每拍都搜索、每拍都更新双池**，但当前正文不等双池；成熟候选在后续拍被原子合并。
- arrival 与连续性互相独立，并行完成后导演才启动（导演依赖两者）。
- 拍后世界链与人物生态模型**并行计算**，但**分支写入严格串行**（world 在前、ecology 在后），
  绝不在模型回调里直接写树——模型谁先完成不改变分支顺序。
- 正文重 Roll 复用旧版 arrival 工件，避免同一比较基准被重新搜索改变；正文改变后 aftermath 必须重跑。
  状态栏重 Roll 不改生态。
- 戏外消息不推进虚构时间。

## 后台双池备料（running / ready 语义）

- **`#ecologyPoolPrep`（running）**：同一引擎同一时刻只允许一条备料链；未完成任务不会被
  下一拍清空或替换，避免多条搜索/全局池/卡池链重叠。
- **`#ecologyPoolReady`（ready）**：任务完成后进入 ready；下一拍**只消费已经就绪**的候选；
  尚未就绪时本拍继续用磁盘现有池，绝不阻塞正文。
- 消费时**重新读取磁盘最新池再 normalize 合并**，避免覆盖 aftermath 刚累计的 `useCount`。
- **所有池写入走同一串行写链 `#ecologyPoolWrite`**：候选合并与 aftermath `applyEcologyUsage`
  都排在这条链上，写前重读最新池，杜绝 stale snapshot 覆盖；写盘用临时文件 + `renameSync` 原子替换。
- 分支切换/回档不写池：池是跨会话素材缓存，`rp-ecology-state` 才是分支权威。

## 搜索源

- **熔断**：DuckDuckGo HTML 被反爬（人机验证页）命中后熔断 30 分钟，期间直接走 Bing，
  不再每条查询先浪费一次无效 DDG 请求。
- `parseBing` / `parseDuckDuckGo` / `isSearchChallenge` 在 `server/web-research.ts`。
- 搜索无可用结果时全局池保持不变，卡池与人物生态仍用已有素材继续推进；每条查询仍会如实回报。
- 支持 `LIYUAN_WEB_RESEARCH_URL` 自定义 POST 搜索后端。

## 工作集（防池膨胀拖慢模型）

磁盘保存完整池，模型只读**相关工作集**：

```text
全局池模型：≤60 条（active、按 useCount 升序）
卡池适配原型：≤60 条
卡级模板工作集：≤50 条
运行态模板：≤40 条
世界书输入：≤50 条
近期历史：≤12~16 条
```

## 相似项治理

- 原型、卡模板和运行事件都有稳定 `patternKey`，按“前提、压力、选择结构、转折功能”识别同构剧情；
  只换人物地点的换皮项合并，不新增副本。
- 合并保留旧 id、累计来源和不同发展；同类但叙事功能真正不同可并存。
- 运行态维护 `recentUses`、`useCount` 与冷却轮次；近期机制不能换皮重开，但既有事件可沿同一 id 继续。
- 多数更新应为 routine/background；每拍通常没有 foreground，最多一个。
- `userRole` 默认 optional；只有历史中用户已明确承诺时才可 committed。生态绝不替用户接受邀请、
  到场、说话、行动、产生感情或作选择。

## 人物认知与社会传播面

- 人物认知属于 `rp-ecology-state`，以带来源的冻结版本保存：目击、被告知、调查、实际送达的消息、
  确实接触的公开渠道或推断。推断只能是怀疑；世界真相变化不会自动刷新人物旧认知。
- occurrence 的 `visibility` 表示镜头/用户发现边界；`publicSurface.publicity` 表示社会传播边界。
  `trace` 只允许公开痕迹，不能泄露秘密原因；舆论和传闻是既有事件的只读传播面，不建立第二事件权威。
- 后台人物按 `lastAdvancedRound / nextDueRound` 进入饥饿保护候选；普通工作、休息、通勤和等待都是
  合法推进，不为完成结算制造事故。多人共同经历沿用同一 occurrence，不能自动共享知识。
- ecology 提交前由 TS 校验认知引用和通讯送达：`message` 认知只能来自已送达且收件人匹配的
  communication occurrence，`public-channel` 只能来自真正 public 的传播面；失败整轮降级，保留旧事实。
- `resolved / expired` occurrence 是终态，普通生态推演不能重开；后续发展必须新建 occurrence 并以
  `causedBy` 引用旧事件。发出不等于送达，送达也不等于相信。

## 日历投影

- `rp-state.time` 仍是“现在”的唯一权威；历法规则来自 `institution-calendar` 的公开
  `calendar-definition` rule，日历 UI 只是 world/ecology 已提交记录的确定性投影，不写回状态。
- 支持内置公历与固定月长自定义历法、自定义周长、日期序号、跨月多日事件、跨年年度重复及相邻月浏览。
  非法日期拒绝投影，不静默钳制；秘密事件不进入普通日历。
- 制度安排写 world record 的 `date/end/recurrence`，人物具体预约与活动仍写 ecology occurrence；
  同一事实不建立第二份日历事件权威。

## 世界/生态跨域信号

世界与生态继续并行、互不写对方状态，但会读取**上一份已提交快照**派生的只读信号
（`src/stage/literary-world-signals.ts`）：

- **世界 → 生态**（`worldSignalsForEcology`）：制度、组织、规则、宏观压力的后果
  （校历、宵禁、城门关闭、交通中断、市场压力、灵潮、宗门命令、区域灾害）。生态据此调整
  人物日程、地点活动和具体机会，但不复制或改写世界模块状态。
- **生态 → 世界**（`ecologySignalsForWorld`）：人物生活、场所活动、局部事件可能升级为宏观
  影响的信号。世界据此判断是否升级，但只通过 `originRefs` / `kernel.links` 引用，不复制
  生态的 actor/location/occurrence。
- 双方同拍不等待对方新输出；对方本拍新结果最迟下一拍可见，换取并发与分支确定性。
- 审计检查目标模块是否把外域 signal 原文复制成新的权威实体。

## 失败语义

- 全局池/卡池/拍前/拍后任一阶段失败都有**明确过程提示**，不再静默空转。
- **拍后 aftermath 失败也落一轮 `degraded` 生态快照**：生态轮次正常前进一次，
  人物/事件/秘密/场所全部保留，记录失败阶段与原因；失败不增加模板使用次数。
- 拍前 arrival 失败沿用上一快照（不影响正文，导演/主演正常推进）。
- 旁路模型流式接口异常时自动做一次**非流式降级**（`compat.streaming=false`）再失败。
- 分支切换期间完成的拍后结果整体丢弃（世界、审计与生态都写，要么都不写）。

## 信息边界

- 主演只收到公开信息、合理可发现条件和“存在秘密”的边界，不收到秘密正文。
- 前端默认展示公开与待发现信息；幕后真相必须二次点击明确揭示。
- 联网查询不得发送私人卡全文、用户对话或无公开出处的私人角色名。

## 与分轮流程的关系

生态系统只扩大拍前事实与候选空间，不写正文、不代替导演、不生成长期剧本。
`beat_plan → draft_append → 回看重评估 → draft_seal` 骨架不变；用户仍可忽略、拒绝或错过世界提供的机会。

## 剧情卡—生态适配（2026-09-02）

`ecologyCard` 持久化的 `worldGrammar`、`actorGrammar` 与 `templates` 是剧情卡的长期生态语法；
它不是单纯背景标签，而是把通用叙事原型变形成当前世界、人物关系和日常活动的规则层。

每拍 arrival 之后、导演之前运行 `plotAdaptation`：先按地点、人物、时间、活跃大纲线和用户输入做确定性相关性排序，再从全局原型池与卡池模板各取最多 12 条工作集；读取当前生态运行态、
已提交大纲、当前状态、近期正文与用户输入，产出至多一个本拍候选和两个储备候选。候选必须说明改造事件、
为何此刻、涉及人物、因果连接、可埋线索、入场方式、本拍推进上限与玩家空间。它们永远不是已发生事实。

适配候选完成后交给导演统一判断本拍压力、人物主动性和玩家停点。角色动机由导演在同一次调用中综合处理，不再按出场人数逐个调用模型排演；主演仍可选择、变形或弃用候选。
只有主演实际交出的正文才由场记、生态 aftermath 和大纲校准为后续事实，候选本身不写入 `rp-state`。

导演与适配候选再交给 `sceneConductor`。它只编排当前场景的一次行动链：谁先行动、可见反应、
局势变化、信息边界与玩家停点；不写正文、不新增事实、不替用户行动。该工件与导演、适配候选一同保存，
正文重 Roll 复用同一套拍前因果材料；正文成功落树后，既有 OutlineEngine 才根据实际正文异步 reconcile，
低风险更新自动提交，高风险主线/伏笔修改仍等待用户确认。

## 资源保护（小 VPS 实测教训）

- **sessions 请求风暴**曾因前端无限循环 + 服务端高成本会话列表扫描吃满单核：已加三层保护——
  前端 pending 门、服务端并发请求合并、同一 WS 每秒最多处理一次会话列表。
- 生态旁路调用全部走旁路插头，可在小机器上为生态步骤换轻量模型。
- 单拍只有一个生态流水线；备料链单飞（running 唯一）+ ready 消费 + 串行写链，杜绝并发写覆盖。
