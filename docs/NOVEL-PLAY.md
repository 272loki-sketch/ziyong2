# 小说开演：实施状态

当前交付为未接入界面的领域模块。还不能从界面上传小说后直接开演，不应作为完整插件发布。

## 已实现

- `source.ts` 复用 CorpusEngine 的分章、分块和默认块大小，不新建上传或消化管道。创建内容指纹及精确原文证据定位。局部指纹不修复现有上传去重方式。
- `canon.ts` 校验阶段、节点、因果依赖、证据与作品包版本。导演候选限制在当前阶段，按字符预算省略完整候选；分支冲突沿显式因果依赖传播。
- `extract.ts` 通过依赖注入复用宿主模型调用。严格解析事件 JSON，要求唯一原文引用，确定性生成证据区间和节点 ID。每块最多两次尝试，支持取消。成功块逐块发布检查点，缓存与新输出使用相同校验。
- `skills/小说作品构建/SKILL.md` 保存事件提取提示词，不在 TypeScript 硬编码提示词。通过现有 Skill 扫描按目录装载，支持用户覆盖，暂未新增 workflow 枚举。
- `store.ts` 复用 readJsonFile，持久化不可变版本包，校验输入结构与版本。文档标识仅作为哈希输入，不能组成任意磁盘路径。采用临时文件及硬链接原子发布，需文件系统支持硬链接。
- `service.ts` 把现有 corpus 文档和文本、Skill、提取器、检查点与存储串联。复用完成块，同一进程内拒绝同文档并行构建。宿主尚未调用此服务，没有另建后台调度器。
- 新增领域、存储、提取与构建服务测试。

## 当前明确限制

作品包只有事件和阶段，尚无人物、关系、世界事实、知情检查点。初版阶段按现有分块形成，不等于语义篇章分段。

只有块内显式因果引用，没有跨块依赖推导。引用匹配仅证明文字存在，不证明模型解释正确。无事件块目前会失败，尚需处理前言等无事件材料。

导演候选投影不是 writer 安全投影，公共标记不构成严格防剧透保证。祖先链与冲突证据由宿主提供，尚未接入 Session Tree。没有实际自动偏差校准或重 Roll 集成。

版本包源数据包含原文分块，仅供提取和证据验证，不能全量发送到 writer。文件存储不提供多进程构建锁。
