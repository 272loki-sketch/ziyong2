# 主演 API 兼容与降级说明

> 当前实现基线：2026-09-18。本文只讨论 `StageEngine` 的主演 writer；导演、场记、世界、生态、摘要等旁路属于普通文本调用，遵守各自的 JSON/文本解析契约。

## 1. 结论

主演 API 不需要会写代码，但需要满足以下两类能力之一：

1. 支持原生 function/tool calling，并能回放 assistant tool call 与 tool result。
2. 不支持工具，但能一次返回完整的小说正文。此时使用纯文本降级模式。

API 禁止模型输出代码，不等于不能写小说；“禁止代码内容”和“不支持函数工具”是两件不同的事。

## 2. 运行模式

### 完整工具模式

模型/API 能接受工具清单并产生标准工具调用时，运行：

```text
beat_plan → draft_append → 回看/重拟 → draft_seal
→ world_state_update 或场记兜底 → 拍后世界/生态 → 独立谢幕
```

该模式提供分段流式正文、检索、局部改稿、账本工具、ask、媒体和 MCP 等能力，具体取决于配置和依赖注入。

### 声明式纯文本模式

模型对象的 `compat.supportsTools` 明确为 `false` 时，首次请求不发送 `tools`，system prompt 改为纯文本主演协议。模型应直接返回本拍完整正文，不输出函数名、JSON、DSML 或工具说明。

正文收取后，harness 会自动收稿、尝试封笔，随后继续场记、拍后世界/生态、摘要和记忆旁路。此模式不伪造 `beat_plan`、`draft_append` 或 `world_state_update` 的调用记录。

### 错误触发的自动降级

如果首次工具请求收到明确的工具不支持错误，或模型返回文本化 tool protocol，例如：

```text
400 tools are not supported
<｜DSML｜invoke name="draft_append">...</...>
draft_append({"segment":"..."})
```

引擎会清除协议文本的实时展示，撤掉工具清单，并以纯文本主演协议重试一次。普通网络错误和 429 不会直接触发降级，而使用有限恢复和 provider 退避。

## 3. 能力矩阵

| API 能力 | 正文 | 分段 | 主动检索 | 局部改稿 | 主演记账 | 旁路任务 |
|---|---:|---:|---:|---:|---:|---:|
| 原生工具调用完整 | 支持 | 支持 | 支持 | 支持 | 支持 | 支持 |
| 接受工具但模型偶尔直出文本 | 支持 | 降级 | 不稳定 | 不稳定 | 场记兜底 | 支持 |
| 明确 `supportsTools:false` | 支持 | 不提供 | 不提供 | 不提供 | 场记兜底 | 支持 |
| 工具请求被拒后自动降级 | 支持 | 降级 | 不提供 | 不提供 | 场记兜底 | 支持 |
| 只返回文本化伪工具协议 | 重试后支持 | 不提供 | 不提供 | 不提供 | 场记兜底 | 视旁路文本是否可解析 |
| 只会自然语言且 JSON 不稳定 | 可尝试 | 不提供 | 不提供 | 不提供 | 可能失败 | 大多降级或跳过 |

## 4. 旁路模型

旁路调用不发送 function tools，主要要求是普通文本和可解析结构：连续性、导演、生态、世界事实/提案/审计、场记、摘要和记忆提取。

不支持工具的 API 可以胜任这些旁路，只要能按要求返回文本或 JSON。解析失败通常是局部降级，不应阻塞正文；场记失败会保留旧账本，世界审计失败会保留旧世界快照。

## 5. 运行时保护

- 主 writer 单次流请求硬超时 15 分钟。
- `ask` 等待硬上限 30 分钟，并响应 abort。
- 单拍检索最多 3 次。
- 工具/API 重试不能无限叠加；引擎层只做有限恢复，provider 层负责退避。
- 工具不兼容降级最多触发一次。
- 旧式 OpenAI Chat `function_call` 会转换为统一工具调用；文本化 DSML 不会直接落树。

### 5.1 正文输入构成诊断

正文不额外硬裁剪正常历史。当前输入语义是：

- 压缩前：当前分支的活跃历史和本拍装配内容。
- 压缩后：`rp-summary`、最近保留正文和按需的有限剧情记忆召回。
- 角色卡原始 JSON、小说全文和全部世界书不作为正文请求的独立全量输入。

每条 assistant 定稿 details 的 `rpInputComposition` 记录初次 writer 请求的字符构成：system、summary、history、injection、latest user、tool schema 以及合计 `initialChars`。该字段用于发现异常输入增长，不改变 writer 的正常历史语义。

### 5.2 外部服务边界

NovelAI 仅用于图片生成和相关媒体交付，不是正文生成、记账、世界推进或记忆召回的必要依赖。NovelAI 凭证过期时图片任务失败属于外部服务配置问题；正文主链仍应按无媒体或降级结果完成。

## 6. 配置示例

对明确不支持工具的 OpenAI 兼容端点声明：

```json
{
  "compat": {
    "supportsTools": false,
    "streaming": false
  }
}
```

如果端点支持工具但不支持单独字段，只声明对应字段能力，例如 `supportsReasoningEffort:false` 或 `supportsStrictMode:false`，不要把整个模型错误标为纯文本模式。

## 7. 不保证的能力

纯文本降级不能保证每段之间的用户介入点、模型主动检索、`draft_edit`、主演主动记账、ask、媒体/MCP/助手工具调用。这些能力需要完整工具模式。

无论哪种模式，正文都必须通过 `StageEngine` 落树，系统事务不能由旁路模型直接冒充正文事实。
